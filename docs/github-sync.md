# GitHub 多设备同步

沿用托福网站 `toefl-study/src/domain/githubSync.ts` 的方案：本地缓存 + GitHub Secret Gist，使用 GitHub REST API 读写专用 JSON 文件。Gist 本身是 Git 仓库，可在 GitHub 查看版本历史。

## 使用

在“我的书桌 → 多设备同步”中填写具有 Gist 读写权限的 GitHub 访问令牌，点击“连接并合并数据”。可沿用托福网站的权限配置。每台设备分别连接同一账号，自动查找已有的 `japan-study-journal-progress.json`；找不到才新建 Secret Gist。

高级设置可指定留日手记的 Gist ID。托福的 Gist、公开 Gist、其他账号的 Gist 或不符合格式的文件均拒绝写入；找到多个匹配文件时要求明确指定，避免误连。

同步范围：考试资料／真题收藏、练习作答与错题状态、题目收藏、笔记、作答草稿、练习日期。筛选条件、题单位置留在本机；最近阅读仍保持移除。原始资料和 PDF 不进入同步文件。

连接后，数据变更延迟 1.5 秒合并同步；打开页面、恢复联网或回到页面时也会尝试同步。无持续轮询或后台常驻任务。可手动“立即同步”或“仅拉取”；仅拉取不会上传本地修改。

## 数据与冲突

- 本地收藏仍使用 `japan-study-journal:desk:v1`，练习仍使用 `japan-study-journal:practice:v1`。
- 令牌和 Gist ID 单独保存在 `japan-study-journal:github-sync:v1`，不会写入 Gist、网站源码、收藏导出或练习导出。
- 合并元数据保存在 `japan-study-journal:sync-state:v1`；收藏删除保留同步标记，防止旧设备复活已取消收藏。
- 每个题目的笔记、草稿、收藏、作答状态分别合并。同一字段以较新修改为准，相同时间按设备标识确定结果。作答状态整组采用较新版本，不将两台设备的累计次数简单相加。
- 首次连接的历史收藏使用原收藏时间；历史练习尽量使用已有更新时间。没有独立时间的旧字段不能精确推断先后，优先已同步的新版本。
- 首次连接前在本地保留 `japan-study-journal:sync-initial-backup:v1`，包含当时的收藏与练习数据，可通过“导出连接前备份”取出。此备份不含令牌。
- 拉取后先合并本机尚未上传的修改，再写入本地；写入失败会尽力回滚，停止覆盖云端。更新后再次拉取复核，发现并发修改时重新合并，最多三轮；持续冲突时保留本机合并结果并提示重试。GitHub Gist 更新接口不提供本实现可依赖的跨设备事务，不宣称原子写入；设备再次同步后收敛。
- 空题库或旧题库保留暂时不认识的题目记录，避免覆盖另一台设备已有数据。
- 同步文件限制 3 MB，收藏仍限制 200 条。超限、损坏、权限不足和断网均给出错误，不把空文件当作远端数据覆盖本地。

Secret Gist 不公开列出，但不是加密的私密存储，知道链接的人仍可能读取笔记。只在可信设备保存令牌。断开连接只移除当前浏览器的令牌与连接，保留本地数据和云端文件；连接期间取消或清空收藏会同步到其他设备。

## 验证

核心测试覆盖合并收敛、删除同步、旧设备首次连接、错误文件／权限／存储失败、断开时取消在途任务和令牌隔离。CI 使用模拟 GitHub API 和独立浏览器配置验证多设备收藏、练习、笔记、离线恢复、旧题库、导出与手机布局，不使用真实个人令牌或真实 Gist。
